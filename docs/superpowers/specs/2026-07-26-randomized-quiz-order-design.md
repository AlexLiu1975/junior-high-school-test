# 題目與選項隨機排列設計

日期：2026-07-26

## 目標

降低學生以背誦固定題號或固定選項字母作答的可能性。每次開始新的測驗時，系統都重新排列 20 題題目及每題四個選項；同一次測驗期間順序保持固定。

## 使用者體驗

1. 學生輸入有效的專屬代碼與姓名。
2. 身分驗證成功後，系統建立該次測驗專用的隨機題目順序。
3. 每題選項也獨立隨機排列。
4. 學生使用上一題、下一題時，已建立的順序不會改變。
5. 完成測驗或重新開始下一次測驗後，再建立一套新的隨機順序。
6. 畫面只顯示該次測驗的「第 1～20 題」，不顯示原始題號。

## 資料與計分設計

原始題庫仍保留穩定的 `q1`～`q20` 題目 ID，錯題次數、複習排程與歷史資料繼續以這些 ID 對應。

開始測驗時，系統建立一份作答用題目：

- 題目順序以 Fisher–Yates 演算法排列。
- 每個原始選項轉換成帶有 `isCorrect` 標記的作答選項，再各自進行 Fisher–Yates 排列。
- 學生答案以題目 ID 記錄所選作答選項的索引。
- 計分時讀取該次作答題目的 `isCorrect`，不再假設原始 `correct: 0～3` 仍是畫面上的正確位置。
- 完成後的錯題檢討使用同一次作答題目資料，因此顯示的選項字母與學生當時看到的內容一致。

Firestore 的測驗紀錄格式與既有進度資料不需變更。

## 程式邊界

新增獨立的純函式模組負責：

- 不修改輸入陣列的 Fisher–Yates 洗牌。
- 將原始題目轉換為可安全隨機排列、仍可判斷正確答案的作答題目。
- 接受可注入的亂數函式，讓測試結果可重現。

`App.jsx` 只負責在身分驗證成功及重新測驗時建立作答題目，並在畫面、計分與錯題檢討中使用這份資料。

## 例外處理

- 若題庫為空，系統不開始測驗並顯示可理解的錯誤。
- 洗牌函式不改動原始 `QUESTIONS`，避免多次測驗互相污染。
- 未完成本次測驗前重新整理頁面，維持目前既有行為：回到測驗入口；不新增中途續答範圍。

## 驗證標準

自動測試必須證明：

1. 題目排列後數量、ID 集合與原始題庫完全相同，沒有遺失或重複。
2. 每題選項排列後數量與文字集合不變。
3. 每題恰有一個正確選項。
4. 使用固定測試亂數時，題目與選項順序確實改變且結果可重現。
5. 選擇洗牌後的正確選項仍會計為正確。
6. 重新開始會建立新的作答題目；同一次測驗的上一題／下一題不會再次洗牌。
7. 原有學生身分、作答保存、教師／家長紀錄、lint 與正式建置測試仍通過。

## 不在本次範圍

- 不顯示原始題號。
- 不保存或顯示亂數種子。
- 不由後端產生試卷。
- 不新增題庫、抽題比例或難度分層。
- 不改變 Firestore 資料結構或安全規則。
