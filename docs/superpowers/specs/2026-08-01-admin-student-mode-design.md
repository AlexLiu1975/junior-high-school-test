# 管理員「我的學生」模式設計

## 目標

讓管理員 `beyle931224@gmail.com` 不必送出並自行核准權限申請，也能以家長身分建立自己的學生、取得學生專屬代碼並查看其歷次測驗紀錄。同時保留既有管理功能，以及一般教師與家長的申請審核流程。

## 使用者體驗

管理員登入教師（家長）紀錄頁後，在頁面右上方看到兩個模式：

- **管理模式**：顯示待審核申請及全部測驗紀錄。
- **我的學生**：顯示管理員自己建立的學生及其測驗紀錄。

首次進入仍預設為管理模式。模式切換只改變頁面顯示內容，不改變登入帳號或管理員的後端權限。

在「我的學生」模式中，管理員可以輸入學生姓名並建立學生。建立成功後，系統使用現有的 Asia/Taipei 日期及每日流水號邏輯，自動產生 `YYYYMMDD-NNN` 格式的專屬代碼。畫面顯示學生姓名與代碼，供該學生使用「專屬代碼＋學生姓名」進入測驗。

管理員不會產生自己的 `accessRequests` 待審核申請，也不需要核准自己。

## 資料模型

沿用現有集合，新增管理員與其學生的歸屬關係：

- `students/{studentId}`
  - 保留現有 `name`、`code`、`active`、`createdAt` 等欄位。
  - 新增 `ownerUid`：建立該學生的管理員 UID。
  - 新增 `ownerType: "admin"`，明確區分管理員直接建立與家長申請建立。
- `studentEntries/{studentCode}/names/{studentName}`
  - 沿用既有學生登入索引，指向 `studentId`。
- `adminStudentLinks/{adminUid}/students/{studentId}`
  - 保存管理員與學生的最小關聯資料，包括 `studentId`、`createdAt`。
- `dailyCounters/{dateKey}`
  - 與家長核准流程共用每日流水號，確保同一天產生的學生代碼不重複。

既有由家長申請核准產生的 `viewerAccess`、`accessRequests` 與學生資料維持不變，不進行資料遷移。

## 資料流程

### 建立管理員自己的學生

1. 前端驗證並正規化學生姓名。
2. Firestore transaction 讀取當日 `dailyCounters`。
3. 產生下一個學生代碼。
4. transaction 同時建立學生、學生登入索引、管理員學生關聯，並更新流水號。
5. 成功後重新讀取「我的學生」清單並顯示代碼。

整個流程必須是單一 transaction；任何一步失敗都不得留下部分學生資料或消耗流水號。

### 查看紀錄

「我的學生」模式先取得 `adminStudentLinks/{adminUid}/students` 的學生 ID，再讀取對應學生資訊。測驗紀錄僅顯示這些學生的 `quizAttempts`。管理模式仍沿用管理員查看全部紀錄的既有查詢。

## 權限規則

- 已驗證的指定管理員可以建立學生、學生登入索引、管理員學生關聯及更新每日流水號。
- 管理員只能在自己的 `adminStudentLinks/{request.auth.uid}` 路徑建立或讀取關聯。
- 一般教師或家長不得使用管理員直接建立學生的流程。
- 一般家長仍只能透過申請、由管理員核准後取得學生關聯。
- 學生匿名登入後仍只能驗證專屬代碼與姓名並建立自己的測驗紀錄，不能列出學生或管理員資料。
- 測驗紀錄不得由教師、家長或管理員修改或刪除。

## 錯誤處理

- 姓名空白、超過 40 字或包含 `/`：在送出前顯示「請填寫正確的學生姓名」。
- transaction 或權限失敗：顯示「學生建立失敗，資料未變更，請稍後重試」。
- 每日流水號超過 999：不建立資料，顯示「今天建立的學生數量已達上限」。
- 清單或紀錄讀取失敗：保留目前模式並顯示明確的載入錯誤，不把錯誤誤顯示成空清單。

## 測試與驗收

- 管理員登入後預設顯示管理模式，且可切換到「我的學生」。
- 管理員不會出現在自己的待審核申請中。
- 建立有效學生會一次寫入學生、登入索引、管理員關聯及流水號。
- 同一天連續建立學生會得到不重複且遞增的代碼。
- transaction 失敗時不留下部分資料。
- 管理員的「我的學生」只顯示自己建立的學生與其紀錄。
- 管理模式仍可顯示全部紀錄與審核其他使用者。
- 一般家長與教師無法直接建立管理員學生關聯。
- 既有家長申請、教師申請、核准、拒絕及學生測驗流程持續通過。
- Firestore emulator 規則測試、前端單元測試、lint 與正式 build 全部通過後才可部署。

## 不在本次範圍

- 管理員刪除學生或變更學生姓名、代碼。
- 將既有家長學生轉移給管理員。
- 多位管理員的管理介面或管理員名單設定頁。
- 允許管理員以一般申請者身分送出並自行核准申請。
