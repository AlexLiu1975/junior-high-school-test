# 多試卷選單與共用雲端紀錄設計

## 目標

將現有生物測驗、英語第 2 回複習考及元素週期表測驗整合到同一個學生測驗入口。三份測驗保留各自適合的操作方式，同時共用學生專屬代碼與姓名驗證、跨裝置進度、每次完成紀錄，以及教師／家長／管理員查詢。

本設計擴充 `2026-08-02-cloud-progress-safe-delete-audit-design.md`。原設計的 Functions 信任邊界、安全刪除、遮罩 IP、離線暫存及角色權限繼續適用；原本單一生物試卷的資料契約改成多試卷登錄表與各題型專用驗證器。

## 已確認決策

- 學生測驗選單提供生物、英語與元素週期表三份試卷。
- 三份試卷都必須輸入「學生專屬代碼＋學生姓名」。
- 三份試卷都保存未完成進度，並可跨手機或電腦接續。
- 三份試卷的每次完成結果都獨立保存，不覆蓋舊紀錄。
- 生物保留現有一次一題及題目／選項隨機排序。
- 英語保留整張 40 題試卷、原題序、閱讀資料、SVG 圖形題、配分與解析。
- 元素週期表保留拖放與點選定位、元素池隨機排列、計時、暫停及重設。
- 元素週期表結果顯示完成數、錯誤次數與完成耗時，不硬換算百分制。
- 新測驗延續管理員安全刪除及管理員專用遮罩 IP 規則。

## 學生導覽

`/junior-high-school-test/quiz.html` 成為試卷選單，沿用網站入口首頁的整排橫條設計，依序顯示：

1. 生物｜第 1 回：細胞與顯微鏡
2. 英語｜第 2 回複習考
3. 化學｜元素週期表

試卷網址使用穩定查詢參數：

- `quiz.html?quiz=biology-cell-microscope-1`
- `quiz.html?quiz=english-review-2`
- `quiz.html?quiz=periodic-table`

選單本身不讀取學生資料。學生點選試卷後才顯示該試卷的姓名及專屬代碼表單。驗證成功後進入試卷；每份試卷都提供「返回試卷選單」及「返回首頁」。未知 `quiz` 值回到選單並顯示「找不到這份試卷」，不載入任意模組。

## 試卷登錄表與模組邊界

前端與 Functions 共用版本化試卷登錄表。每筆至少包含：

- `quizId`
- `version`
- `kind`：`multiple-choice` 或 `placement`
- `subject`
- `title`
- `catalogDescription`
- 對應的前端 renderer
- 對應的後端進度驗證器與完成驗證器

試卷選單只由登錄表產生，不在畫面元件重複寫死三份連結。Functions 只接受登錄表存在的 `quizId + version`，不能由前端傳入任意試卷名稱、題目或正確答案。

每個試卷模組只負責自己的呈現與使用者操作，透過同一介面交給共用學生殼層：

- `createAttempt()`：建立可保存的初始順序與狀態。
- `restoreAttempt(saved)`：驗證後恢復同一份未完成作答。
- `serializeProgress(state)`：輸出允許同步的純資料。
- `buildSubmission(state)`：輸出後端可驗證的完成資料。
- `renderResult(result)`：呈現伺服器確認的結果。

學生身分驗證、同步狀態、本機待送資料、衝突選擇、重送、首頁與選單導覽由共用殼層處理，不在三個試卷模組中複製。

## 生物測驗

沿用現有 20 題、錯題次數與複習排程。每次開始時保存題目順序及每題選項 ID 順序，跨裝置恢復時不得重新洗牌。

後端依版本化題庫與穩定選項 ID 重新計算：

- 百分成績
- 答對題數
- 答錯題數
- 錯題 ID

伺服器成功建立完成紀錄後只清除本次 `activeAttempt`，保留既有錯題次數及複習排程。

## 英語第 2 回複習考

將來源 HTML 的 40 題、五組閱讀資料及 SVG 圖形題轉為版本化資料模組。正式畫面保留整張試卷方式，不改成一次一題：

- 第一部分第 1～20 題，每題 2 分。
- 第二部分第 21～40 題，每題 3 分。
- 題目維持原順序，選項不隨機。
- 未完成時保存每題已選選項及目前捲動定位所需的最後作答題號。
- 提交後顯示答對／答錯樣式與原有解析。

後端不接受前端傳入的總分，依版本化答案與題目配分重新計算百分成績、答對／答錯題數及錯題 ID。未作答題目計為錯誤；提交前畫面顯示尚未作答題數並要求學生再次確認。

來源 SVG 轉成受控 React 元件或靜態 SVG 模組，不使用來源 HTML 字串的任意腳本或事件屬性。

## 元素週期表測驗

將 118 個元素的原子序、符號、中文名稱、英文名稱、分類及正確位置轉成版本化資料模組。正式畫面保留桌面拖放及手機點選後定位兩種操作。

進度保存：

- 本次作答 ID
- 元素池的初始隨機順序
- 已正確放置的元素 ID
- 錯誤放置次數
- 已累積秒數
- 計時狀態：進行中或暫停
- 最後更新時間

跨裝置恢復時沿用原元素池順序與已完成位置。恢復「進行中」狀態時從已累積秒數重新開始計時，不把離線期間計入；恢復「暫停」狀態時維持暫停。

只有 118 個元素全部放在正確位置後才能建立「完整完成」紀錄。後端驗證提交包含每一個合法元素且位置正確，並記錄：

- `completedCount = 118`
- `totalItems = 118`
- `errorCount`
- `durationSeconds`
- `completed = true`

正確完成數可由版本化元素位置驗證。錯誤次數與操作耗時來自瀏覽器累積，屬學習統計而非防作弊成績；後端只接受非負整數與合理上限，畫面及紀錄不得把這兩欄描述成不可偽造資料。重複提交相同作答 ID只建立一筆完成紀錄。

若學生按「結束」但尚未完成 118 個元素，保存未完成進度，不建立正式完成紀錄。重設只清除該試卷的本次進度，不影響另外兩份試卷或歷史紀錄。

## 共用雲端資料

### `studentProgress/{studentId}/quizzes/{quizId}`

每份學生／試卷各自一份文件：

- `studentId`
- `quizId`
- `quizVersion`
- `kind`
- `activeAttempt`
- `reviewProgress`：只有需要複習排程的試卷使用；其他試卷為空物件
- `updatedAt`
- `updatedByUid`

Functions 依 `quizId + version + kind` 選擇專用驗證器。某一試卷的 payload 不能寫入另一種試卷不認識的欄位。

### `quizAttempts/{attemptId}`

共用欄位：

- `quizId`、`quizVersion`、`quizKind`、`quizTitle`、`subject`
- `studentUid`、`studentId`、`studentCode`、`studentName`
- `submittedAt`
- `resultType`：`score` 或 `placement`

選擇題結果：

- `score`
- `correctCount`
- `wrongCount`

元素表結果：

- `completedCount`
- `totalItems`
- `errorCount`
- `durationSeconds`
- `completed`

Functions 根據 `resultType` 寫入固定欄位，不能混用兩種結果形狀。既有生物紀錄缺少新增欄位時仍可讀取，前端以舊格式顯示，不要求破壞性資料遷移。

### `attemptPrivate/{attemptId}`

延續原設計，只保存遮罩 IP 與建立時間，且只有已驗證管理員可讀。

## 教師／家長／管理員紀錄頁

紀錄表新增「科目」並依結果類型顯示：

- 生物／英語：`85 分｜答對 34｜答錯 6`
- 元素週期表：`完成 118／118｜錯誤 9 次｜12分35秒`

搜尋涵蓋學生姓名、專屬代碼、科目及試卷名稱。教師查看全部授權範圍，家長只查看指定學生，管理員可查看全部及遮罩 IP。任何角色都不能修改或刪除完成紀錄。

安全刪除判斷涵蓋三份試卷：學生只要有任一 `quizAttempts` 就只能停用，不能永久刪除。

## 離線、衝突與錯誤

- 本機暫存 key 必須包含 `studentId + quizId`，三份試卷互不覆蓋。
- 本機與雲端都有未同步變更時，顯示試卷名稱、兩邊更新時間及作答進度，讓學生明確選擇。
- 網路中斷先保存本機；恢復連線後只同步目前試卷。
- 正式完成紀錄未獲 Functions 成功確認前，不清除待送資料。
- 試卷版本不相容時不嘗試猜測轉換；保留本機資料並顯示「試卷已更新，請聯絡教師」，避免錯誤計分。
- 某一試卷載入失敗不應使另外兩份試卷無法開啟。

## 安全與隱私

- 三份試卷都由 Functions 驗證學生代碼及姓名，不信任前端 `studentId`。
- 生物及英語成績由後端版本化答案重新計算。
- 元素位置完成狀態由後端版本化位置重新驗證；錯誤次數與耗時清楚標示為操作統計。
- Firestore Rules 繼續拒絕瀏覽器直接寫入進度、正式紀錄及私密 IP。
- 原始 HTML 不得以 `dangerouslySetInnerHTML` 執行題目內容；固定 SVG 必須移除腳本、外部資源及事件屬性。
- 不新增電話、地址、學號或其他學生個資。

## 驗證

自動測試至少涵蓋：

- 試卷登錄表三個穩定 ID、標題、類型及選單順序。
- 未知試卷 ID／版本拒絕。
- 生物隨機順序跨裝置還原及伺服器重新計分。
- 英語 40 題、2／3 分配分、滿分 100、未作答確認、閱讀資料與 SVG 顯示。
- 元素 118 筆唯一性、位置唯一性、桌面拖放與手機點選、暫停／恢復、錯誤次數及完成耗時。
- 三份試卷本機 key、雲端進度及完成紀錄互相隔離。
- 三種結果在教師／家長／管理員頁正確顯示；非管理員無法讀取 IP。
- 任一試卷已有紀錄時，安全刪除改為停用並保留全部歷史。
- 同一作答 ID 重送不重複建立紀錄。
- production build 產生可從 `quiz.html` 開啟的選單及三份試卷。

公開上線後使用測試學生逐一驗證三份試卷的開始、離線暫存、跨瀏覽器接續、完成、教師／家長紀錄與管理員遮罩 IP，再執行安全刪除／停用驗證。
