# 雲端進度、安全刪除與測驗稽核設計

## 目標

讓學生以「專屬代碼＋學生姓名」在不同手機或電腦接續未完成的試卷，並永久保留每一次完成的測驗紀錄。管理員可以安全處理誤建學生，並在測驗紀錄中查看完成時間、學生、試卷、成績及遮罩 IP。

本設計採用 Firebase Callable Functions 作為受信任的資料入口。瀏覽器不直接決定 IP、不直接寫入正式成績，也不能取得完整 IP。

## 已確認決策

- 未完成進度必須跨裝置同步。
- 每一次完成的測驗都獨立保存，不覆蓋舊紀錄。
- 只有管理員可以刪除或停用學生。
- 沒有測驗紀錄的誤建學生可以永久刪除；已有紀錄的學生只能停用。
- IP 只保存遮罩值，且只有管理員可以查看。
- 網路中斷時保留本機暫存，恢復連線後再同步。

## 根因與現況

目前學生程式讀寫 `users/{uid}/quizProgress/{quizId}`，但 Firestore Rules 只允許 `users/{uid}/quizzes/{quizId}`。這會造成 Firestore 拒絕進度讀寫；前端又把設定缺少、權限拒絕及網路錯誤統一顯示成「雲端進度同步尚未完成設定」，因此畫面無法指出真正原因。

即使只修正路徑，目前資料仍以匿名 Firebase UID 區分。同一位學生換裝置會取得不同 UID，所以無法跨裝置接續。為符合已確認需求，進度必須改以核准的學生 ID 與試卷 ID 為主鍵，並由受信任後端驗證姓名及專屬代碼。

## 架構

### 學生端

學生頁仍使用 Firebase 匿名登入，讓 Callable Function 收到可追蹤但不揭露個資的 Firebase Auth UID。學生輸入專屬代碼及姓名後，後端核對 `studentEntries/{code}/names/{exactName}` 是否存在、啟用且對應同一個學生 ID。

受信任函式分成三個明確操作：

1. `loadStudentProgress`：驗證學生後，讀取該學生與試卷的雲端進度。
2. `saveStudentProgress`：驗證學生後，以受控格式覆寫未完成進度。
3. `submitQuizAttempt`：驗證學生、重新檢查成績資料範圍、建立不可修改的完成紀錄，並清除該試卷的未完成進度。

管理端另有 `removeOrDeactivateStudent`，只接受已驗證管理員呼叫，並依是否已有完成紀錄決定永久刪除或停用。

函式輸入不得接受呼叫端指定的 `studentId` 作為權限依據。`studentId` 一律由有效的「代碼＋姓名」查得，避免竄改成其他學生。

### 教師／家長／管理員端

既有 Google 登入與角色核准流程維持。一般測驗資料存放於 `quizAttempts/{attemptId}`，教師、獲授權家長及管理員依既有範圍讀取。

遮罩 IP 獨立存放於 `attemptPrivate/{attemptId}`，只允許管理員讀取。教師與家長不是只在畫面上隱藏 IP，而是在 Firestore Rules 層完全無法讀取該文件。

管理員紀錄表新增「IP」欄。教師與家長沿用時間、學生、試卷、成績欄，不顯示 IP。安全刪除操作放在學生卡片，不放在單筆成績列，避免讓人誤以為可以刪除歷史成績。

## 資料模型

### `studentProgress/{studentId}/quizzes/{quizId}`

保存未完成試卷：

- `studentId`
- `quizId`
- `activeAttempt`：本次作答 ID、已選答案、題目及選項順序、目前位置；只接受目前試卷存在的題目與合法選項識別值
- `reviewProgress`：既有錯題次數與複習排程資料；完成測驗後仍保留
- `updatedAt`：伺服器時間
- `updatedByUid`：最後同步的匿名 UID，僅供稽核，不作學生身分依據

### `quizAttempts/{attemptId}`

每次完成後新增且不可修改。前端提交題目與選項識別值，後端使用與前端共用的版本化試卷定義重新計分，不接受前端提交的分數作為真實成績：

- 既有 `quizId`、`quizTitle`、`studentId`、`studentCode`、`studentName`
- `score`、`correctCount`、`wrongCount`
- `submittedAt`：伺服器時間
- `studentUid`：提交時的匿名 UID

### `attemptPrivate/{attemptId}`

- `maskedIp`
- `createdAt`

文件 ID 與 `quizAttempts` 相同。此 collection 只允許管理員讀取，不允許瀏覽器寫入。

### IP 遮罩

- IPv4 只保留前三段，例如 `203.0.113.xxx`。
- IPv6 只保留網路前綴，其餘顯示為 `…`。
- 後端只把遮罩結果寫入 Firestore，不保存完整 IP，也不得把完整 IP寫入應用程式日誌或錯誤訊息。
- 若平台沒有提供可判定的來源 IP，保存 `無法判定`，不可改用瀏覽器傳入的 IP。

## 跨裝置同步與衝突

學生開始測驗時先載入雲端進度，再與目前瀏覽器暫存比較 `updatedAt`。預設使用較新的版本；若本機有尚未上傳的答案，畫面明確讓學生選擇「繼續本機進度」或「使用雲端進度」，不靜默覆蓋。前端與 Functions 共用同一份版本化試卷定義；題目改版時保留版本號，避免舊進度被新答案錯誤計分。

每次選答案後先寫入本機暫存，再以短暫延遲合併同步至雲端，避免每次按鍵立刻呼叫函式。同步成功後顯示「已同步」及時間；失敗時顯示「已保存在本機，等待同步」。完成測驗時必須由後端成功建立正式成績才顯示「紀錄已保存」。重試使用固定的本次作答 ID，後端據此確保同一次提交不會產生重複紀錄。成功後只清除 `activeAttempt`，錯題次數與複習排程仍保留在 `reviewProgress`。

本機暫存以學生 ID 與試卷 ID 隔離；登出或換學生不會載入另一位學生的答案。

## 安全刪除

只有通過既有管理員電子郵件與已驗證 Google Token 檢查的使用者能呼叫管理函式。刪除按鈕先顯示學生姓名、專屬代碼與影響範圍，管理員必須再次確認。

後端查詢該學生是否已有 `quizAttempts`：

- **沒有完成紀錄**：刪除學生文件、登入對照、進度與複習狀態、管理員擁有關係，以及家長授權中的該學生關聯。流水號不回收、不重用。
- **已有完成紀錄**：不刪除學生、複習狀態與成績；將學生及登入對照設為停用，只清除未完成的 `activeAttempt`，並保留原專屬代碼供歷史紀錄辨識。

安全刪除不提供前端直接刪除 Firestore 文件的權限。所有相關文件由單一管理函式完成，任何中途失敗都回報未完成，不在畫面上假裝成功。

## 安全規則與濫用防護

- `studentProgress`、`attemptPrivate` 及正式成績建立均由 Functions Admin SDK 管理；前端 Firestore Rules 預設拒絕直接寫入。
- `attemptPrivate` 只有管理員可讀，教師與家長皆拒絕。
- Callable Functions 同時檢查 Firebase Auth、輸入長度、資料型別、學生啟用狀態與試卷白名單。
- 管理函式另外檢查已驗證的管理員 Google 帳號，不相信前端傳入的角色。
- 為 Functions 設定合理的最大執行個體數並建立 Google Cloud 預算警示，降低異常流量造成費用的風險。預算警示只負責通知，不能視為自動停用服務。

## 錯誤與復原

學生端分開顯示：

- Firebase 設定缺少
- 學生代碼或姓名不符
- 學生已停用
- 權限拒絕
- 網路中斷，已保存在本機
- 雲端同步衝突
- 完成紀錄尚未成功保存

未完成進度同步失敗不阻止繼續作答；但完成測驗後若正式紀錄尚未成功建立，保留本機待提交資料與「重新送出」按鈕。只有收到後端成功結果後才清除待提交資料。

目前因路徑不一致而未成功寫入的舊雲端進度無法可靠遷移；本次上線後從新的學生進度文件開始同步。既有 `quizAttempts` 完成紀錄保持不變。

## 部署與成本邊界

實作需要初始化及部署 Firebase Functions，並可能要求專案連結 Google Cloud Billing／Blaze 方案。啟用 Blaze 不代表固定月費，但超過免費額度或使用不含免費額度的資源會依用量計費。正式部署前必須：

1. 顯示實際要建立的 Functions、區域及最大執行個體數。
2. 確認專案是否已啟用 Billing。
3. 建立低額預算警示。
4. 先在 Emulator 驗證，再部署 Functions 與 Firestore Rules。

任何 Billing 啟用或外部部署都必須由使用者明確確認；程式完成與本機測試通過不等於已部署。

## 驗證

自動測試至少涵蓋：

- 正確與錯誤學生憑證的進度讀寫。
- 學生 A 無法讀寫學生 B 的進度。
- 題目、答案索引及進度資料格式驗證。
- 同一作答 ID 重試不重複建立成績。
- 完成後建立公開成績、管理員私密 IP 文件並清除未完成進度。
- IPv4、IPv6、未知 IP 的遮罩結果。
- 教師與家長無法讀取 `attemptPrivate`，管理員可以讀取。
- 無成績學生永久刪除完整；有成績學生只停用且歷史紀錄保留。
- 非管理員不能刪除或停用學生。
- 離線暫存、重新連線、跨裝置載入及同步衝突。
- 既有登入、角色、題目隨機化、教師／家長紀錄查詢不退步。

上線後以測試學生驗證：裝置 A 作答部分題目、裝置 B 接續、完成後管理員看到時間／遮罩 IP／學生／試卷／成績、教師及家長看不到 IP，最後分別驗證無紀錄學生的永久刪除與有紀錄學生的停用流程。

## 不在本次範圍

- 保存完整 IP。
- 教師或家長刪除學生、成績或 IP。
- 修改或刪除既有完成成績。
- 學生帳號密碼、忘記密碼或自助更名。
- 回收已使用的每日流水號。
